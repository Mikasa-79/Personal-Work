# 一、系统需求描述

## 1.1 项目背景
大学校园中，学生之间存在大量日常互助需求：快递代取、学习辅导、二手物品交换、活动组队等。  
目前这些需求散落在微信群、QQ群、贴吧等平台，信息碎片化、匹配效率低、缺乏信任机制。

**CampusHub** 旨在提供一个统一的校园互助服务平台，让学生能够方便地发布需求、发现匹配、建立信任、完成协作。

---

## 1.2 用户角色

| 角色 | 描述 |
|------|------|
| **需求方** | 发布互助需求的学生（如“需要人帮忙取快递”） |
| **服务方** | 接单并提供服务的学生（如“我可以帮忙取快递”） |
| **管理员** | 平台管理人员，负责内容审核、用户管理、数据统计 |

> 同一个用户可以同时是需求方和服务方。

---

## 1.3 核心功能模块

### 模块一：用户管理
- 注册/登录（支持学号+密码，或第三方登录）
- 个人资料管理（头像、昵称、学院、联系方式）
- 角色切换（发布需求 / 接单服务）

### 模块二：需求发布与浏览
- 发布互助需求（标题、描述、分类、地点、时间、报酬/交换条件）
- 需求分类体系：快递代取、学习辅导、二手交易、活动组队、其他
- 需求列表浏览（支持按分类、时间、距离筛选）
- 需求详情查看

### 模块三：智能匹配与推荐
- 基于分类、地理位置、时间的基础匹配
- 基于用户历史行为的简单推荐
- 匹配结果排序

### 模块四：订单流程管理
- 接单 → 确认 → 进行中 → 完成 → 评价（完整状态机）
- 双方确认完成机制
- 订单历史记录

### 模块五：评价与信用体系
- 完成订单后双向评分（1–5 星 + 文字评价）
- 用户信用分计算与展示
- 信用等级标识

### 模块六：消息通知
- 站内消息（接单通知、状态变更通知、评价通知）
- 简易即时通讯（需求方与服务方一对一消息）

### 模块七：管理后台
- 用户管理（查看、禁用）
- 需求内容审核
- 数据统计看板（DAU、订单量、分类分布等图表）

---

## 1.4 非功能需求
- **性能**：核心页面加载时间 < 2 秒  
- **安全**：密码加密存储，防止 SQL 注入和 XSS 攻击  
- **可用性**：界面简洁，核心操作路径不超过 3 步  
- **可维护性**：代码结构清晰，关键模块有单元测试

---

## 2.2 工作量合理性分析
- 240 人时开发一个中等规模 Web 应用，在 AI 辅助下可行  
- AI 可显著加速：文档初稿（节省 ~40%）、CRUD（节省 ~50%）、测试用例（节省 ~30%）  
- AI 无法加速：用户访谈、架构讨论、团队协调、反思日志  
- 编码阶段（第6–7周）最紧张  
- 建议提前搭建框架，弱基础团队可缩减 P2 功能

# 三、核心设计理念：每阶段的「AI 协作三问」

每次阶段验收需记录在《AI 协作反思日志》中：

### Q1 — AI 在哪里帮了我？
- 哪些任务交给了 AI？
- 效果如何？
- 附 Prompt 日志与输出截图

### Q2 — AI 在哪里误导了我？
- AI 输出中的错误、遗漏、歧义
- 如何识别并修正

### Q3 — 下次如何让 AI 更好地工作？
- Prompt 策略反思
- 至少一条改进措施并在下阶段验证
