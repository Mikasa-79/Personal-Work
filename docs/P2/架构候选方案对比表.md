| 对比维度 | 方案 A：分层架构 + MVC | 方案 B：微服务架构 |
|---------|------------------------|------------------|
| 开发复杂度 | 较低。系统可分为表现层、控制层、业务层、数据访问层，结构清晰，适合课程项目。 | 较高。需要拆分多个独立服务，并处理服务通信、部署、注册发现等问题。 |
| 可维护性 | 较好。各层职责明确，修改功能时影响范围较小。 | 理论上很好。每个服务可以独立维护，但需要较强的服务治理能力。 |
| 可扩展性 | 中等偏好。可以通过模块化方式增加新功能，如消息模块、信用分模块、管理员模块。 | 很好。不同业务服务可以独立扩展，例如任务服务、用户服务、消息服务。 |
| 性能 | 能满足当前项目需求。校园互助平台规模有限，单体后端加数据库足够支持演示。 | 性能潜力更高，但需要额外的服务治理和部署能力，对本项目可能过度设计。 |
| 团队学习成本 | 较低。Vue、Spring Boot、MySQL、RESTful API 都是常见技术，资料较多。 | 较高。需要学习服务拆分、服务间调用、网关、配置管理、容器部署等内容。 |
| 10 周内可行性 | 高。适合在有限时间内完成设计、开发、测试和展示。 | 较低。架构工作量大，可能影响核心功能完成。 |
