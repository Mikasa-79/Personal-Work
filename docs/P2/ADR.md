# ADR-001：后端选择 Java 还是 Go

## 状态
已接受

## 背景
校园互助平台后端需要支持用户认证、订单流转、数据访问和接口服务，需要选择适合项目需求的后端开发语言。

候选方案包括使用 Java（基于 Spring Boot）或 Go 进行后端开发。

## 决策
我们决定采用 Java 作为后端开发语言，并基于 Spring Boot 构建 REST API 服务。

## 理由
1. Java 生态成熟，与 Spring Boot 集成完善，适合快速开发业务系统。
2. 更适合事务型业务处理，与 MySQL 配合稳定。
3. 团队对 Java 技术栈熟悉，学习成本较低。
4. 相较 Go，更适合当前课程项目规模与开发周期。

## 后果
- 正面影响：开发效率较高，生态成熟，维护成本较低。
- 负面影响：相比 Go 运行性能和资源占用可能略逊。
- 需要关注的风险：需要控制 Spring Boot 项目复杂度，避免过度设计。

## AI 辅助记录
- AI 初稿内容摘要：比较 Java 与 Go 两种后端语言，并建议采用 Java + Spring Boot。
- 人工修订内容：在后果中添加负面影响被忽略的原因是，项目定位决定了系统对性能要求相较于运行的稳定性来说优先级较低，java相应的生态更加成熟，掩盖了其性能上的不足。
- 修订理由：AI未能根据项目的定位和相应属性的优先级进行分析，仅机械罗列二者的各自优缺点。

# ADR-002：前端采用独立 Vue 单页应用还是传统多页架构

## 状态
已接受

## 背景
校园互助平台需要支持动态交互、页面路由跳转、状态管理与表单校验，需要选择合适的前端架构模式。

候选方案包括 Vue 单页应用（SPA）和传统多页应用（MPA）。

## 决策
我们决定采用独立 Vue 单页应用（SPA）作为前端架构。

## 理由
1. Vue 组件化开发适合复杂交互场景。
2. 前后端分离模式与 Spring Boot REST API 匹配良好。
3. 路由与状态管理更适合任务流转类业务。
4. 用户体验较传统多页架构更流畅。

## 后果
- 正面影响：提升交互体验，便于功能扩展和模块维护。
- 负面影响：前端工程配置复杂度略高。
- 需要关注的风险：需要做好路由权限控制和接口联调。

## AI 辅助记录
- AI 初稿内容摘要：比较 SPA 与传统多页架构，并建议采用 Vue 单页应用。
- 人工修订内容：添加理由：VPA的性能上初始加载后，后续请求仅获取数据（JSON），可通过懒加载路由优化首屏。且Vue的Pinia状态管理可跨页面保持用户登录状态、筛选条件或未读通知，避免重复登录或数据丢失。
- 修订理由：Ai未能抓住VPA本质的性能优势在于作为校园互助平台前端，用户相应的更追求轻量化使用体验，在此背景下VPA的Pinia状态和初始加载的优势被进一步放大。

# ADR-003：高并发应对策略的选择

## 状态
已接受

## 背景
CampusHub平台可能面临用户注册高峰、需求发布集中期或订单流转高峰，导致并发请求增加。现有架构为前后端分离+分层单体，数据库MySQL，后端Spring Boot，前端Vue SPA。需要评估高并发风险并选择合适的应对策略，避免系统崩溃或性能下降。

候选方案包括启用Redis缓存限流、优化数据库连接池、引入负载均衡，或保持现状不做额外优化。

## 决策
我们决定暂时不改变架构，但启用Redis作为可选组件，用于限流和短期缓存，以应对潜在高并发场景。

## 理由
1. Redis可用于API限流（如每用户/分钟请求上限），防止恶意攻击和突发流量过载。
2. 缓存热点数据（如需求列表、用户会话），减少数据库查询压力，提升响应速度。
3. 相比引入微服务或负载均衡，Redis集成简单，适合P0阶段，避免过度设计。
4. 平衡开发成本和性能需求：仅在未读通知计数、限流等明确场景启用，保持架构简洁。

## 后果
- 正面影响：提升系统并发处理能力，改善用户体验，降低数据库负载。
- 负面影响：增加Redis依赖和配置复杂度，可能引入缓存一致性问题。
- 需要关注的风险：Redis单点故障需监控，缓存失效策略需设计，避免缓存穿透。

## AI 辅助记录
- AI 初稿内容摘要：分析高并发风险，推荐启用Redis用于限流和缓存，理由包括简单有效和适合项目阶段。
- 人工修订内容：添加理由：考虑到实际使用场景和访问人数，我们决定暂时不升级架构到微服务架构，原因是本项目使用范围仅限制在学生之间，使用人数不超过3000人，最高在线峰值预估不超过500人，微服务架构带来的复杂维护和开发无法和其提升的性能相平衡。
- 修订理由：加入了对未来使用场景的预估，通过假设未来使用情况进行决策。
