## 2. AI 助力分析（Q1）
本阶段 AI 最大的贡献是：
- 快速整理出“分层架构”与“微服务架构”之间的对比维度，帮助团队在候选方案分析阶段形成清晰的评估表格。
- 提供了结构化的架构建议和模块划分思路，使我们能够更快完成“架构辩论赛”和架构设计文档的初稿。

不同 Prompt 策略下 AI 回答质量的差异：
- 直接提问时，AI 给出的建议较为通用，缺少对项目周期、团队能力和课程项目约束的具体分析。
- 提供详细约束后，AI 能给出更贴合团队实际的架构风格推荐，并能直接回答为什么不采用微服务等方案。
- 要求对比多种方案时，AI 的优势在于列出优缺点，但仍需要我们团队补充项目实际落地风险。
- 扮演架构师角色时，AI 更关注实际情况下，针对该项目的实际用途进行分析，输出最适合作为最终决策参考的论证。

## 3. AI 误导分析（Q2）
AI 在架构建议中的典型问题：
- 问题1：把 MVC 直接当作完整架构方案推荐。
  - 如何发现：团队在“架构辩论赛”中讨论后发现，MVC 更适合作为实现设计思想，而不是顶层架构风格。
  - 如何修正：我们将最终架构定位为“前后端分离 + 后端分层单体”，并把 MVC 作为后端实现时的代码组织思路。
- 问题2：过度推荐微服务或事件驱动架构。
  - 如何发现：结合项目 10 周周期、4 人团队和课程项目目标，发现这些方案会增加开发与部署复杂度。
  - 如何修正：团队明确把“可交付性”和“团队学习成本”作为第一优先项，最终放弃微服务与完整事件驱动架构。
- 问题3：AI 初稿有时遗漏“AI 协作辅助能力与局限性”这一质量属性。
  - 如何发现：在撰写 ADR 和本阶段文档时，我们补充了 AI 初稿与人工修订的对比内容。
  - 如何修正：通过人工审查补充 AI 推荐的质量属性权衡，确保决策记录完整。

## 4. Prompt 改进计划（Q3）
上阶段（P1）提出的改进措施，验证结果：
- 改进措施：在 Prompt 中增加“项目周期、团队熟悉技术、核心功能、交付目标”这些约束。
- 验证结果：本阶段详细约束输入显著提升了 AI 的回答可落地性，尤其在架构风格选择和技术选型部分质量提高明显。

本阶段新的改进措施：
- 未来 Prompt 要进一步明确“课程项目优先级”、“10 周内完成的最小可行系统（P0）”、“团队已有技术栈”和“避免过度设计”的具体要求。
- 在询问 AI 时，额外补充“团队是否存在部署/运维经验”与“是否需要 Docker Compose 展示环境”等实际交付条件。
- 对 AI 输出进行结构化校对，按“可行性 / 可维护性 / 可扩展性 / 风险”四个维度快速打分，避免只看单一推荐。

## 5. 本阶段的核心工程判断
决策内容：
- 采用“前后端分离 + 后端分层单体”架构。
- 前端技术栈定为 Vue 3 + TypeScript + Vite + Pinia + Element Plus。
- 后端技术栈定为 Spring Boot 3 + MyBatis-Plus + Spring Security + JWT + MySQL 8，Redis 作为可选缓存组件。
- 部署建议采用 Docker Compose + Nginx 静态资源 + Spring Boot 应用 + MySQL 容器，避免过度引入微服务治理。

为什么 AI 无法做这个决策：
- AI 缺少对团队真实交付能力、项目进度、成员分工和课堂评分标准的现场认知。
- AI 能给出候选方案和风险说明，但因为缺少对于实际运用场景的思考，不能替代团队对“10 周可实施性”和“课程项目验收目标”的最终判断。
- 因此，AI 的最佳作用是辅助生成架构对比、记录讨论过程和提醒潜在风险，而最终决策必须由团队结合实际能力和项目时间窗口做出。
