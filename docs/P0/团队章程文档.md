## 二、 详细评估记录

### 1. AI 编程助手 (AI Code Assistant)
*   **候选工具 A：** **Cursor** (最终选择)
    *   **选择理由：** 具备 Codebase 全局索引功能，能理解跨文件引用，极大提升了复杂业务逻辑的编写速度。其“Tab”自动补全功能比普通插件更智能。
*   **候选工具 B：** **GitHub Copilot**
    *   **不选择理由：** 虽然稳定性好，但在处理整个项目结构的重构和多文件协同修改时，交互体验不如 Cursor 这种原生 AI 编辑器顺畅。

### 2. AI 对话工具 (AI Chat Tool)
*   **候选工具 A：** **Claude 3.5 Sonnet** (最终选择)
    *   **选择理由：** 在理解复杂的软件架构设计和生成结构化文档（如本项目的 P1-P3 文档）时，逻辑性更强，幻觉较少。
*   **候选工具 B：** **ChatGPT (GPT-4o)**
    *   **不选择理由：** 在长代码片段的生成中容易出现截断或逻辑跳跃，对中文语境下的学术/工程描述偶尔不够精准。

### 3. AI 代码审查工具 (AI Code Review)
*   **候选工具 A：** **CodeRabbit** (最终选择)
    *   **选择理由：** 能够自动在 GitHub Pull Request 中发表评论，指出潜在的逻辑漏洞，并提供直接可用的重构建议，符合团队的质量保障流程。
*   **候选工具 B：** **AI Code Review (GitHub Action)**
    *   **不选择理由：** 预设模板较死板，针对复杂业务逻辑的审查深度不足，往往只能检查出语法层面的小问题。

### 4. AI 测试工具 (AI Testing Tool)
*   **候选工具 A：** **CodiumAI** (最终选择)
    *   **选择理由：** 专注于测试用例生成，能根据代码路径自动分析并补全边缘测试点（Edge Cases），非常契合本项目 P6 阶段的质量保障要求。
*   **候选工具 B：** **通义灵码 (Test Generation)**
    *   **不选择理由：** 生成的单元测试相对基础，主要覆盖了“快乐路径”（Happy Path），对复杂 Mock 环境的支持不如 CodiumAI 专业。

---

## 三、 结论建议

本次选型优先考虑了 **“对代码库的深度感知能力”** 以及 **“与 GitHub 工作流的无缝集成”**。所有选定工具均提供免费额度，符合团队零成本协作的需求。

**全体成员共识：** AI 仅作为生产力辅助，所有输出内容必须经过人工审查方可合入 `dev` 分支。
